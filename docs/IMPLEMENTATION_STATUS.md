## Current app and safety features

### C. Agentic AI safety decision engine — source implementation checklist

- [x] Deterministic, testable state machine covering journey monitoring, possible distress, emergency activation, provider-accepted alerts, live emergency tracking, and resolution.
- [x] Combines timestamped confidence signals from scream/shout/vocalization classification, exact personalized SOS phrase matches, fall detection, route deviation, and missed check-ins inside a bounded recent-evidence window.
- [x] An enabled independent SOS phrase activates immediately. Less-certain signals can request a check-in; an unanswered check-in escalates automatically. Fall plus strong distress sound and configured multimodal combinations can also activate without a button press.
- [x] Manual SOS now enters the same state machine. Emergency activation is deduplicated locally and server-side; provider failures do not get marked as sent, and emergency tracking can continue if notification delivery fails.
- [x] Stores a bounded per-journey decision trace (state, reason, timestamps, signal kinds/confidence/IDs; no transcripts or raw audio) and retains the native monitor's persisted emergency/retry state across service interruptions.
- [ ] Validate the full foreground/background transitions, duplicate suppression, provider outcomes, and recovery on the user's current Android phone. Model confidence thresholds and classifier behavior remain unvalidated; this implementation is not a guarantee of detection or delivery.

### D. Continuous live location — source implementation checklist

- [x] Uses real Expo device GPS in foreground and a top-level Android background location task during an authorized active journey; records coordinates, horizontal accuracy, and device timestamp.
- [x] Rejects invalid, inaccurate (>100 m), stale (>30 seconds), and out-of-order fixes; marks displayed coordinates stale after 30 seconds and retains the last accepted fix during GPS/network loss.
- [x] Publishes through the owner-authorized `publish_journey_location` RPC; dashboard reads are limited by journey owner/shared-contact RLS and refresh through Supabase Realtime. Location timestamps are shown on the device and dashboard.
- [x] Normal background cadence is 5 seconds/5 m; emergency mode requests 2 seconds/1 m when Android and the device permit. Background publication retries the newest saved point at the next fix.
- [x] Route deviation uses point-to-polyline distance, user-selected thresholds plus GPS accuracy, and three consecutive off-route fixes before notifying contacts. Foreground and background checks share the configured route and threshold.
- [x] The mobile app now shows an interactive street map with live marker, accuracy radius, recent trail, planned route, stale indicator, and visible OpenStreetMap attribution. The family dashboard's realtime Leaflet map now also draws the shared planned route and destination.
- [ ] Google Maps API credentials are not configured. This release uses OpenStreetMap tiles to provide a real in-app map without a Google Cloud key; the public tile service is best-effort. Device validation of GPS cadence, background behavior, route alerts, and realtime dashboard is still pending.

- Android foreground monitor captures mono 16 kHz PCM through `AudioRecord`, normalizes it to YAMNet's float waveform, and analyzes overlapping 0.975-second windows at a 0.48-second hop. On-device YAMNet classifies shouting, screaming, crying, infant cries, whimpering, and wailing/moaning; a cry/wail alone can request a check-in but cannot independently activate SOS. Classifier events carry the audio-window capture timestamp and confidence into the safety decision engine; inference metadata logging is opt-in and stores no raw microphone samples. Microphone/model errors are surfaced and retried with bounded delays. Personalized trigger phrases use the installed English on-device OS speech model while the app is foregrounded; exact transcript matches honor each phrase's independent-activation setting. Android may omit ASR confidence scores, so the engine distinguishes an absent score from a low score and does not invent a score. The background service still does not transcribe custom phrases; no arbitrary phrase keyword-spotting model has been selected or validated. Classifier thresholds and performance remain unvalidated. Web preview does not run safety monitoring.
- Browser builds now resolve a separate speech-monitor adapter that does not load the native speech-recognition module; browser voice monitoring remains intentionally unavailable and must show that state. The web preview has not yet been exported after this fix.
- Speech engine assessment: Android `SpeechRecognizer` can stream partial/final transcripts from an installed offline locale, and Android 13+ can receive contextual strings that bias recognition toward a user's phrase. Contextual strings are not a constrained grammar or a guaranteed keyword spotter. The OS/vendor owns the offline model; its memory use, latency, phrase recall, and redistribution license cannot be controlled or reported consistently by this app and have not been measured on the Honor X5c. The app therefore waits for a final exact transcript and uses YAMNet separately for background distress sounds. No arbitrary phrase recognition is claimed for the background service.
- YAMNet is a pretrained general-audio classifier, not validated for this app. An opt-in Android settings control now stores only per-window predicted class, confidence, timestamp, threshold, and inference latency in app-private storage (20,000-row/4 MB cap); it never records microphone samples. A text share-sheet export shares up to 200 CSV rows at once, and users can clear the local log. The blank `actual` labels still need a consented, representative corpus. Scream detection precision/recall, false positives per hour, false negatives, memory/battery impact, and environmental limits remain unknown. Fall thresholds are heuristics.
